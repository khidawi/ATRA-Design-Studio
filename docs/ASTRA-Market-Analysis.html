Where ASTRA fits in the market for AI governance and assurance¶

Market analysis for ASTRA, an assurance platform for AI agents and AI models. Prepared 22 October 2026.

How to read this notebook

  • Market-size figures and vendor facts come from public web sources gathered on the date above; they are listed at the end. Where sources disagree, both are shown.
  • The capability scores in section 4 are my qualitative reading of public descriptions (0 = little or none, 1 = partial, 2 = core to the category), at category level, not product by product. ASTRA's scores come from this repository. Treat the scores as a starting point to challenge, not as measured fact.
  • Vendors change quickly (several were acquired in 2025). Check a vendor's own documentation before quoting it to a customer.

What this says. Everyone agrees the market is small today and growing at 30% or more a year. They disagree by an order of magnitude on how big it is, because "governance platform" (a narrow software category) and "TRiSM" (governance plus security plus runtime controls) are different things. For ASTRA the sensible planning assumption is the narrow category: roughly half a billion dollars in 2026, with the broader TRiSM spend around it as the pool to win from.

What this says. Runtime guardrails (blocking prompt injection, filtering data in the request path) were the first part of the market to be bought up by network and endpoint-security companies. That is a strong signal that enforcement in the request path is becoming a feature of the security stack, which is a hard place for a new entrant to compete. Governance, assurance and evidence across the lifecycle has no equivalent consolidation yet.

3. What ASTRA actually is (from this repository)¶

Area In ASTRA today
Design time Agent and model designers; OWASP Agentic Top 10 rules evaluated on the design; ST-AI scoring (PCS, seven-metric risk vector) with a crosswalk to NIST AI RMF, ISO/IEC 42001, ISO/IEC 23894 and the EU AI Act
Agent contract A ratified contract per agent; its design, version and allowed tools, data, MCP servers, handoffs and memory
Agent runtime SDK and OpenTelemetry intake of event names; each event judged against the contract; findings mapped to OWASP; drift items that compliance decides; regression tests drafted from findings
Model runtime Production monitors that keep hourly statistics only (drift against thresholds, canaries, safety flags, versions); decision records on how people use outputs (rubber-stamping, wrong outputs accepted)
Assurance Assurance gap, evidence packs, attestations that expire, audit trail, roles and sign-off
Deployment Self-hosted with Docker Compose; vendor-neutral (works with models and agents it does not host)
Not in ASTRA Runtime enforcement (it records a halt request; it cannot stop an agent), adversarial or red-team testing, a live threat-intelligence feed

6. How ASTRA differs¶

  1. Contract-versus-reality for agents. Most agent products either manage identity (who the agent is) or block bad prompts. ASTRA compares what an agent did with what compliance approved it to do, and turns any difference into a finding mapped to OWASP and a drift decision for a human.
  2. Agents and models on one platform. Governance vendors tend to cover models and use cases; observability vendors cover models; agent tooling covers agents. ASTRA scores, monitors and evidences both with one method (ST-AI) and one audit trail.
  3. Evidence that expires. Attestations and packs have a lifetime and are re-opened when production evidence turns against them, so a green status cannot go stale.
  4. Human-use analytics. Rubber-stamping and accepted-wrong-output rates, by role, with privacy by default (names dropped unless compliance signs off). I found no equivalent in the other groups' public descriptions, but absence from a web search is not proof.
  5. Privacy-minimal by design. It reads inputs as they pass and keeps hourly statistics and event names, not records or content, which lowers the barrier for regulated and small organisations.
  6. Self-hosted and vendor-neutral. One Docker Compose deployment; works for models it does not host (Ollama, a hosted API) because it monitors what the organisation's own application sends and receives.

7. Honest gaps and what to do about them¶

Gap Why it matters Realistic response
No real-time enforcement Security buyers expect blocking; ASTRA records a halt request only Position as the assurance layer above a guardrail product; integrate with one (for example accept its events and verdicts) rather than build an AI firewall
No adversarial testing Red-teaming is a standard buyer question Import results from a test tool as evidence into the pack
No live threat feed The OWASP and ST-AI library is curated, not fed Versioned library updates, and imports of rule sets, with a view of which agents change status
Brand and reach Incumbents are bundled into products customers already own Start where bundles do not reach: small and mid-size organisations, start-ups and academic or sector pilots (such as IADS), and organisations running mixed or self-hosted models
Unproven in production No reference customers yet A shared test with colleagues, then two or three design partners with a measured before/after

8. Suggested positioning line¶

ASTRA is the assurance layer for organisations that run AI agents and AI models: it proves, from design through production, that each one still does what it was approved to do, and keeps the evidence an auditor will ask for.

It sits beside identity, guardrail and observability tools, not instead of them.
